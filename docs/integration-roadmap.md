## 需要逐步扩展的接口

1. **坐标与时序**：通过 TF2 将检测姿态转换到明确的规划坐标系；拒绝过期检测和不可用变换；输送带上需要速度估计、拦截时间和重定位。
2. **运动 action**：现有 `MoveArm` 是短时 mock 服务。真实运动需目标姿态/约束、规划与执行反馈、取消、停止确认及明确错误码；只有实际机器人配置完成后才能定义规划组和末端 link。
3. **抓取 action**：提供候选抓取、接触/保持反馈和取消；夹持失败不能继续搬运。具体关节目标或力限制必须来自已确认的硬件和安全要求。
4. **任务与恢复**：增加任务取消、幂等操作 ID、持久化、目标过期、控制器断连及恢复策略。真实硬件任何失败后应先进入受控停止/人工恢复流程，不能沿用当前 mock 的“继续下一个目标”。
5. **物理验收**：逻辑模拟成功仅验证消息和调用顺序。Gazebo 接触仿真、碰撞验证、实机低速验收和硬件急停验证是独立工作，不能互相替代。

下一里程碑先归档现有静止抓取的运行环境、程序、K5/RY-H1 驱动及 L515 标定；从录制数据和只读状态开始核对接口，再复用已确认的模型完成离线规划、仿真与轨迹验证。
已在现场完成静止抓取不代表本仓库已具备相同能力；在适配和验证完成前，默认启动仍保持软件模拟。
