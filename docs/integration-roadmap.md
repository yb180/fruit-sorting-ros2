# 后续接入评估

本阶段保留感知输入、分拣目标、机械臂请求和手部请求的边界，先验证软件数据流。硬件型号、运动学和驱动协议尚未给定，因此本仓库没有假设这些参数。

| 组件 | 需提供/确认的输入 | 建议接入边界 | 接入前验证 |
| --- | --- | --- | --- |
| 相机与真实识别 | 实际驱动、图像/深度/CameraInfo、模型类别及置信度、时间同步、标定 | 新感知节点发布现有 `DetectionArray`；稳定对象 ID 由跟踪器产生 | 离线数据准确率、深度有效性、TF 转换、时间戳、未知类及低置信度行为 |
| MoveIt 2 | 真实 URDF/SRDF、规划组、末端执行器、关节限位、运动学配置、PlanningScene | 新运动适配层消费规划目标；用 action 提供反馈、取消和执行结果 | 先只规划，再在仿真中验证碰撞、可达性、路径和停止；不可直接替换 mock 并启动实机 |
| Gazebo | 与 Ubuntu 22.04/Humble 兼容且固定版本的仿真发行版、机器人/手/场景模型 | 使用仿真控制器实现运动和抓取适配层，统一 `/clock` 与 `use_sim_time` | 仿真启动、控制器状态、接触/摩擦、抓取保持和故障恢复；当前未选择 Gazebo 具体发行版 |
| 真实机械臂控制器 | 实际厂商协议或 ros2_control 硬件插件、joint_states、轨迹控制器及命名 | 在仿真验证后接入 `FollowJointTrajectory` 或厂商明确文档支持的接口 | 限速、限力、急停、工作空间、通信超时、停止确认、反馈可信度及人工审核 |
| 灵巧手 | 实际关节/驱动/反馈、抓取模式、力或触觉测量、安全限值 | 将 `close/open` 演示命令演进为带抓取候选、反馈和取消能力的 action | 空载及仿真验证，按蔬果建立抓取力/变形策略，不凭空生成关节角或抓取力 |

## 需要逐步扩展的接口

1. **坐标与时序**：通过 TF2 将检测姿态转换到明确的规划坐标系；拒绝过期检测和不可用变换；输送带上需要速度估计、拦截时间和重定位。
2. **运动 action**：现有 `MoveArm` 是短时 mock 服务。真实运动需目标姿态/约束、规划与执行反馈、取消、停止确认及明确错误码；只有实际机器人配置完成后才能定义规划组和末端 link。
3. **抓取 action**：提供候选抓取、接触/保持反馈和取消；夹持失败不能继续搬运。具体关节目标或力限制必须来自已确认的硬件和安全要求。
4. **任务与恢复**：增加任务取消、幂等操作 ID、持久化、目标过期、控制器断连及恢复策略。真实硬件任何失败后应先进入受控停止/人工恢复流程，不能沿用当前 mock 的“继续下一个目标”。
5. **物理验收**：逻辑模拟成功仅验证消息和调用顺序。Gazebo 接触仿真、碰撞验证、实机低速验收和硬件急停验证是独立工作，不能互相替代。

建议下一里程碑先使用已确认的机器人模型在仿真中实现“规划但不执行”和轨迹回放，再引入真实相机离线录制数据；在这些验证完成之前继续保留本项目的模拟隔离。
